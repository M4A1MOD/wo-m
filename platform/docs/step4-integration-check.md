# 第四步：三服务接口联调记录

测试日期：2026-09-20。

## 环境和范围

- 前端 Vite：127.0.0.1:5173；后端 Spring Boot：8080；AI FastAPI：8000。
- 使用前端 `/api/v1` 代理入口发起 HTTP 请求，验证前端代理 → 后端 → AI 服务链路。
- 后端使用临时内存数据库 `jdbc:h2:mem:integrationcheck;MODE=MySQL`；测试课程已删除。
- 本轮没有安装新软件。后续安装软件、下载工具和可配置缓存优先使用 D 盘独立目录。
- 本轮未做浏览器点击、实际麦克风录音、声音播放、PPTX 可编辑性或导出页面交互验收。

## 已修复的联调阻塞

最初 8 个 AI POST 接口直连 FastAPI 返回 200，但经过 Spring Boot 均返回 500。FastAPI 日志出现 `Unsupported upgrade request` 和请求体缺失的 422 错误。

后端 `AiLessonController` 的 RestClient 显式使用 HTTP/1.1，避免 JDK HttpClient 默认 HTTP 升级与当前 Uvicorn 配置不兼容。修改后重新编译、启动，8 个接口均经前端代理返回 200；未新增依赖。

## 尚未通过的功能检查

1. 同一课程分别询问顶点和光合作用，回答完全相同；AI 答疑尚未利用问题实际生成答案。
2. 输入课程时长 20 分钟，响应课程时长为 20，但场景时长之和为 45。
3. 知识图谱只输入一个知识点时，有 2 条边引用不存在的节点。
4. 课程生成前端发送 `content_style`，Java DTO 接收 `contentStyle`，该字段无法按当前字段名正确传递；现有 AI 模板也未使用它。
5. 源码显示课程生成/答疑失败时前端会展示本地模板，用户看到生成结果不能证明完整调用链成功。
6. 源码显示上传 PDF/PPTX 只在前端建立资料条目，未调用后端资料解析；发布状态只写入 localStorage，未调用课程更新接口。
7. 后端课程实体仅保存基础信息；前端加载服务器课程时会重新补齐模板内容，完整课堂内容持久化仍需专项验收。

## 结论

基础服务链路和课程 CRUD 已验证，AI POST 通信阻塞已修复。真实模型、文档解析、多模态生成和语音能力仍不能按需求判定完成。下一阶段应优先处理上述功能缺口，并安排浏览器操作与导出文件专项测试。
