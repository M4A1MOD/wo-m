# Demo 0.5 更新说明

## 版本定位

Demo 0.5 是相对原始 Demo 0.4 的累计功能更新版本，覆盖课程工作区调整、真实模型交互、导图重构、资源管理、配图与导出、绘图白板、项目流程、用户配置和 Windows 启动交付。

本轮工作生成 0.5 文档，并更新文档入口；应用代码内仍有 0.4 版本标识，详见验收记录的“版本兼容说明”。

## 相对原始 0.4 的主要变化

| 原始模块/体验 | 0.5 文档归档的当前实现 |
|---|---|
| 多模块平铺，课程上下文不明显 | 工作台与创建课堂为一级入口，进入课程后展开准备、教学、复盘；可回工作台换课 |
| 主题生成对教学要求的表达不足 | 创建课堂新增选填课程描述，与参考资料一起作为真实模型生成上下文 |
| AI 接口配置与复用不便 | 设置页管理密钥、模型和自定义 URL，保存到项目外用户配置目录，重启可读取 |
| 模型接入以云端接口为主 | 新增 Ollama 提供商、模型列表读取和本机 OpenAI 兼容调用；无 Ollama 不阻止平台启动 |
| 思维导图缺少真正树形结构 | 使用规范嵌套 JSON、四级限制、短语节点、来源标记及增删改/展开收起/导出 |
| 知识关系图与课程关联不足 | 基于当前课程生成分层节点及关系，支持来源追踪、编辑、筛选和 JSON/SVG 导出 |
| “双 AI 音频”用途不清楚 | 改为当前场景的“角色对话朗读”，明确是浏览器朗读，非预生成音频文件 |
| 互动教材和学习分析演示成分较多 | 增加教材笔记、收藏、完成进度；分析使用实际作答，未测时无预设成绩；时长仍含估算 |
| 协同讨论依赖模板 | 按角色携带最新对话调用真实模型，记录员根据已有发言整理笔记；无真实模型时明确阻止讨论 |
| 学科资源与创建课堂重复 | 调整为课程资料存档、下载、删除及网课/参考链接管理 |
| 配图入口与独立图片应用分离 | 集成火山引擎视觉文生图到课程场景，图片落盘并用于课件与 PPTX |
| 白板主要展示文字板书 | 增加 SVG 绘图、几何工具、公式文本、撤销重做、规则图解排版及 PNG/SVG 导出 |
| 项目学习主要提供任务描述 | 增加分组、阶段、成果上传、反馈、评价量规及项目级加权得分 |
| 文本 PPTX 与简单课堂 ZIP | PPTX 增加图片嵌入及动画转场结构；ZIP 增加讨论、白板、幻灯片描述和项目数据 |
| 启动依赖本机路径与多条命令 | 根目录提供一键启动/停止，自动准备项目依赖并检查服务就绪 |

## 使用路径

1. 准备 Node.js 20+、Python 3.11+、JDK 17+，将项目解压到合适位置；建议在 D 盘预留依赖与资源空间。
2. 双击根目录 `一键启动.cmd`，首次联网准备依赖后访问 `http://localhost:5173`。
3. 在“系统设置”配置云端模型或本机 Ollama；图片生成单独配置火山引擎接口。
4. 创建课堂，按需填写描述和上传参考资料；在教学工作台选择课程进入工作区。
5. 依次进行课程准备、课堂教学与课后复盘；对应操作和限制见 [功能矩阵](Demo0.5功能矩阵.md) 与 [验收记录](Demo0.5验收记录.md)。
6. 保存课程，按需导出资料；使用结束后双击 `一键停止.cmd`。

## 无 Ollama 下载者的使用方式

- 平台不会安装 Ollama、启动其服务或下载模型。
- 默认示例配置允许演示，Ollama 模型名为空；首次没有个人配置时可进入演示模式。
- 也可以在设置中配置 DeepSeek、通义千问、Kimi 或 MiniMax，不依赖本机 Ollama。
- 真实协同讨论、边读边想和简答题 AI 批改需要至少一个可用真实模型；演示模式不能替代这些功能。
- 若已选择 Ollama 并填写模型，但本机未启动服务，将收到连接错误；若服务可连但没有模型，刷新列表会提示尚无模型。模型由用户通过 Ollama 自行管理。

## 配置与分享

Windows 下个人配置默认位于：

```text
%APPDATA%\ZhixueTeachingPlatform\llm-providers.json
%APPDATA%\ZhixueTeachingPlatform\image-provider.json
```

原图片应用的用户配置可在本机首次使用配置读取流程时迁移；迁移来源也是当前用户目录，不是随项目携带的凭据。以上文件目前为明文 JSON，项目外存放并不等于加密。

源码通过 Git 分享时，`.env`、运行资源目录、数据库、依赖、原图片应用和开发缓存由忽略规则排除，`.env.example` 仅包含空值或占位值。提交前仍应检查暂存区；忽略规则不对已跟踪文件或手动压缩生效。

不要直接把整个开发工作目录当作干净发布包：普通 ZIP 压缩不会读取 `.gitignore`，可能携带 `.env`、上传资料与课程数据库。建议分享 GitHub 仓库的源码下载包，并让接收者自行配置 API。
