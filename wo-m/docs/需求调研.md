# 智能互动教学平台需求调研报告

版本：V1.0  
日期：2026-09-07  
阶段：需求评审与 Demo 0.1 后续开发输入

## 1 调研结论

智能互动教学平台面向教师和学生，核心目标是把“备课、课堂生成、互动学习、测验反馈、学情沉淀”连接成一条可演示、可保存、可继续扩展的业务闭环。结合项目现有 Demo 0.1，第一阶段不应一次性开发全部规划功能，而应优先完成 P0 功能：用户登录、课程管理、课堂生成、教师审核、互动课堂、测验与反馈、知识库基础检索。

技术选型确定为：前端 Vue 3，业务后端 Spring Boot 3 加 Spring Data JPA，AI 服务 FastAPI，关系数据库 MySQL，向量检索首版使用 PostgreSQL pgvector 或 Chroma 二选一。大语言模型通过 LangChain 适配，图像识别预留 YOLOv8 接口，模型训练预留 PyTorch 或 TensorFlow 目录。业务后端是统一业务入口，AI 服务只承担生成、检索、识别和模型推理，不直接管理用户权限与核心业务状态。

## 2 项目现状

项目已有 Demo 0.1 单页原型，包含工作台、生成课堂、互动课堂和知识库页面，并以“牛顿第二定律”为演示主题。当前交互主要依赖浏览器本地模拟数据，已经验证“输入主题、生成课堂结构、进入课堂、答题并获得反馈”的用户路径，但尚未形成真实的数据持久化、模型调用和教师审核流程。

现有材料还包含项目内容说明、四周开发计划和一版需求规格说明书。本次工作以这些项目材料为需求依据，收敛范围并补齐图示、非功能需求、接口边界与工程目录。

## 3 干系人与核心诉求

| 角色 | 核心任务 | 主要诉求 | 验收关注点 |
| --- | --- | --- | --- |
| 教师 | 上传资料、生成课堂、编辑审核、发布课堂、查看结果 | 降低备课成本，生成内容可控可改 | 生成结果可保存，审核后才能发布 |
| 学生 | 进入课堂、查看场景、提问、答题、查看反馈 | 学习过程有互动，反馈及时易懂 | 能完成完整课堂并看到解释性反馈 |
| 管理员 | 管理用户、课程、配置和日志 | 权限清晰，异常可追踪 | 关键操作留痕，敏感配置不泄露 |
| 项目组 | 分工开发、联调、演示和迭代 | 接口边界明确，版本可以稳定回退 | 前后端和 AI 端可独立启动与测试 |

## 4 业务范围

### 4.1 P0 必须完成

1. 用户注册、登录、退出和角色权限控制。
2. 课程新增、查询、修改、删除和状态管理。
3. 输入主题或课程资料，生成结构化课堂大纲与场景。
4. 教师编辑生成内容并执行通过或退回审核。
5. 学生进入互动课堂，按场景学习并向 AI 教师提问。
6. 生成测验、提交答案、自动评分并返回解析和建议。
7. 保存课程、场景、题目、答题记录与问答记录。
8. 资料上传、文本解析、分段和基础检索。
9. 模型不可用时使用模拟数据降级，保证演示主链路不中断。

### 4.2 P1 应该完成

1. 知识点标签和包含、前置、相关三类知识关系。
2. 学习结果页、错题建议和基础学情统计。
3. 课堂导出为 HTML 或 JSON。
4. 操作日志、统一错误码、模型调用日志和重试策略。
5. 教师端与学生端的响应式页面适配。

### 4.3 P2 后续规划

1. TTS 语音授课与 ASR 口语输入。
2. 复杂知识图谱和多智能体编排可视化。
3. YOLOv8 图像识别教学实验。
4. PyTorch 或 TensorFlow 专用模型训练与部署。
5. 3D 仿真、多人实时课堂、PPTX 高保真导出。

## 5 核心业务流程

### 5.1 教师生成并发布课堂

教师登录后创建课程，输入主题、年级、学科、课时和教学目标，可选上传参考资料。系统保存草稿并调用 AI 服务；AI 服务检索相关资料，生成大纲、场景、知识点和测验草稿；业务后端校验结构并保存。教师编辑内容，审核通过后发布课堂。若模型超时、返回格式错误或服务不可用，系统提示原因并允许重试或切换模拟数据。

### 5.2 学生互动学习

学生进入已发布课堂，按顺序浏览情境引入、概念讲解、交互实验和即时测验。学生可围绕当前场景提问，系统把课程主题、当前场景和检索片段传给 AI 教师。学生提交答案后，客观题由规则评分，简答题可由模型辅助评价，最终保存成绩、解析、知识点掌握情况和复习建议。

## 7 非功能需求

1. 性能：普通业务接口 P95 不高于 2 秒；AI 首次响应目标不高于 8 秒；长耗时操作必须展示状态。
2. 可用性：Demo 阶段核心链路连续执行 3 次不得出现阻断性错误；模型失败必须支持重试或模拟降级。
3. 安全：密码强哈希加盐保存；生产环境使用 HTTPS；接口按角色授权；API Key 通过环境变量注入；日志不得记录密码、令牌和完整敏感资料。
4. 可维护性：前端、业务后端、AI 服务分目录；统一响应格式和错误码；关键模块具备基础单元测试。
5. 兼容性：支持 Chrome、Edge 等主流现代浏览器；页面在 1366 像素桌面和常见移动宽度下不出现主要内容溢出。
6. 数据保护：课程和学习记录定期备份；删除操作需权限校验；上传文件限制类型和大小。

## 8 技术选型

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3、Vite、TypeScript、Pinia、Vue Router、Axios | 与现有 Vue 方向一致，适合快速组件化和前后端联调 |
| 业务后端 | Java 17、Spring Boot 3、Spring Data JPA、Spring Security | 承担用户、课程、审核、答题等核心业务和权限 |
| AI 服务 | Python 3.11、FastAPI、LangChain | 统一封装生成、RAG、问答、识别和训练推理能力 |
| 关系数据 | MySQL 8 | 保存用户、课程、场景、题目、记录与审核状态 |
| 向量检索 | pgvector 或 Chroma | Demo 阶段二选一，封装在 AI 服务内部 |
| 图像识别 | Ultralytics YOLOv8 | 作为可插拔能力，通过 FastAPI 暴露接口 |
| 模型训练 | PyTorch 优先，TensorFlow 可选 | 独立训练目录与业务代码隔离 |
| 接口 | REST JSON，必要时 WebSocket | REST 用于业务操作，WebSocket 预留流式响应和课堂实时状态 |

## 9 架构原则

1. Vue 前端只调用 Spring Boot 业务接口，不直接持有模型密钥。
2. Spring Boot 管理身份、权限、业务状态、事务和持久化，并通过内部接口调用 FastAPI。
3. FastAPI 不重复建设用户和课程 CRUD，只接收必要上下文并返回结构化 AI 结果。
4. 所有模型输出先按 JSON Schema 校验，再进入业务数据库。
5. RAG 检索、YOLO 推理和训练模型以适配器方式接入，允许替换供应商和实现。
6. Demo 默认提供 mock 模式，真实模型和向量库不可用时仍可完成汇报演示。

## 10 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 模型输出格式不稳定 | 前端无法展示或数据无法保存 | 强制 JSON Schema，解析失败重试，最后降级模拟数据 |
| 四周范围过大 | 核心链路无法按期完成 | P0 优先，P2 只保留接口和目录，不阻塞版本 |
| 资料解析质量不一致 | RAG 回答偏离资料 | 首版限制文件类型、分段长度和文件大小，保留来源片段 |
| 前后端字段频繁变化 | 联调返工 | 先冻结 OpenAPI 与 DTO，再独立开发 |
| 模型密钥或学生数据泄露 | 安全事故 | 环境变量、脱敏日志、权限校验、最小化采集 |

## 11 Demo 0.1 后续开发建议

第一步先将现有静态页面迁移到 Vue 3，并让“最近课堂、生成课堂、课堂详情”读取后端数据；第二步实现课程、场景、题目和答题记录 CRUD，形成 Demo 0.2；第三步接入真实大模型、结构化生成和问答，形成 Demo 0.3；第四步补充知识库、教师审核、结果页、导出和测试材料，形成可稳定汇报的 Demo 0.4。
